# Preferências do Usuário

## Desenvolvimento

* Linguagens principais: **JavaScript e Python**
* Outras linguagens: C, C#, PHP, SQL, Node.js, HTML e CSS
* Backend preferido: **Python + FastAPI**
* Frontend preferido: **React**
* Desenvolvimento atual: principalmente **Web**
* Banco de dados: prefere **SQLite** pela simplicidade; possui mais experiência com MySQL
* ORM: nenhum preferido
* Editor: **VS Code**
* Sistemas: **Windows**, com interesse em Ubuntu/Linux
* Versionamento: **Git + GitHub**
* Terminal: principalmente terminal integrado do VS Code e CMD

## Inteligência Artificial

* API mais utilizada: **Groq**
* IA local: **Ollama**
* Modelo local para conversas: `llama3.2:3b`
* Modelo local para código: `qwen2.5-coder:7b`
* Preferência entre API e local: depende dos limites e da quantidade de uso; preferir API quando houver limite amplo
* Não há framework de IA preferido

## Forma de Trabalho

* Preferir **arquivos completos** ao alterar código
* Para alterações pequenas, um trecho pode ser suficiente se o local da alteração for explicado claramente
* Trabalhar **passo a passo** quando possível
* Preferir soluções **simples e diretas**
* Aceitar maior complexidade quando houver benefício significativo
* Priorizar automaticamente as tecnologias preferidas
* Manter arquivos e responsabilidades **bem separados e organizados**
* Código deve usar nomes de variáveis e funções em **inglês**
* Comentários: poucos, somente quando necessários
* Idioma da interface: depende do projeto

## Decisões Técnicas

* Priorizar soluções **gratuitas ou de baixo custo**
* Evitar tecnologias caras, excessivamente complexas ou desnecessárias
* Quando houver alternativas gratuitas, simples e adequadas, priorizá-las
* Evitar adicionar bancos, serviços ou infraestrutura quando não forem realmente necessários
* Considerar opções gratuitas de hospedagem quando aplicável
* Ao existir mais de uma solução válida, **apresentar as opções e perguntar antes de decidir**
* Não adicionar complexidade apenas por questão de arquitetura

## Observações

Estas preferências servem como orientação para decisões técnicas e de desenvolvimento. Preferências específicas de um projeto podem substituir estas regras quando necessário.
